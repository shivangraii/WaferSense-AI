Agenda

What this is, what it does, who it is for.

WaferSense AI works on wafer maps: the pass/fail picture of every die on a silicon wafer after electrical testing. Each map is a small grid where 0 is background, 1 is a passing die and 2 is a failing die. It is a software prototype for decision support, not a replacement for a test engineer.

01 · The input

Which wafer map?

Wafer-bin maps from the public WM-811K set (811,457 maps, 172,950 labelled). The model reads them as 64×64 grids and sorts them into nine classes: Center, Donut, Edge-Loc, Edge-Ring, Loc, Near-full, Random, Scratch and none.

02 · What it does

Name the pattern, show the proof

A CNN predicts the defect pattern with a confidence score. Grad-CAM then highlights the dies that drove the decision, and anything under 60% confidence is flagged for a human to check.

03 · What it helps with

Faster triage, less eyeballing

Failure shape points at the upstream cause: edge rings often suggest etch or deposition edge effects, scratches suggest handling or polishing, and centre clusters suggest process non-uniformity. Sorting thousands of maps automatically gives engineers a head start.

Quickly group failing wafers by pattern and see where the model looked.

Decision-support prototype only. It recognises spatial patterns on labelled maps; it does not inspect physical wafers, diagnose root causes or certify quality.

Why it matters

A wafer map is a fingerprint of the process.

Every die on a wafer is tested. Where the failures land forms a shape, and the shape points at what went wrong upstream. Reading those shapes by eye does not scale to hundreds of thousands of maps.

Classify

A compact CNN sorts each map into Center, Donut, Edge-Loc, Edge-Ring, Loc, Near-full, Random, Scratch or none.

Explain

Grad-CAM highlights the region of the wafer that pushed the score, so an engineer can check the model against the map.

Review

Predictions under 60% confidence are flagged for a person to look at, instead of being passed off as certain.

From raw maps to a live model

Six stages, one reproducible pipeline.

Training runs on a free Colab GPU. The saved model and metrics ship with the site, so the dashboard needs no dataset to run.

Load

WM-811K wafer maps

811,457 maps are read from the original pickle. Only the 172,950 that carry a failure label are kept.

Preprocess

Resize without blending

Each map becomes 64×64 using nearest-neighbour sampling, so background, pass and fail values never mix. Three one-hot channels feed the network.

Balance and split

6,000 per class, stratified 70 / 15 / 15

The dominant “none” class is capped, giving 27,839 maps. The test set stays untouched until the final evaluation.

Train

Random Forest baseline, then the CNN

Class-weighted loss handles imbalance. Augmentation is limited to flips and 90° rotations, which keep the label intact on a round wafer.

Explain

Grad-CAM on the last conv block

Class-score gradients weight the final feature maps and upsample to the wafer, giving a heatmap over the dies behind the prediction.

Deploy

Streamlit dashboard, live on the web

Six pages cover inspection, explainability, analytics, model performance and an exportable report.

Questions

What people ask first.

Which dataset does it use?

WM-811K, a public set of 811,457 wafer maps from real fabrication, of which 172,950 carry a failure-type label. The raw data is about 2 GB and is not shipped with the site; only the trained model and its metrics are.

Can I try my own wafer map?

Yes. On the Wafer Inspector page, upload a .npy or .csv array with 0 for background, 1 for a passing die and 2 for a failing die. Wafer-map images also work, converted approximately by brightness.

How should I read the heatmap?

Warm regions are where the network’s score for the chosen class was most sensitive. It is a coarse inspection aid. It does not prove cause, and it does not prove the prediction is right.

Is it ready for a production line?

No. It is a decision-support prototype trained on one public dataset and may not carry over to other fabs, tools or process nodes. The split is stratified by label rather than grouped by lot, so lot-level leakage is possible.
